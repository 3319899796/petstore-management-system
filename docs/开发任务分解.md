## L2 宠物档案 + 主人档案

**交付**
- `owner`：登记/编辑主人，手机号列表脱敏（`138****8000`）
- `pet`：新增/编辑/删除（逻辑守卫）、分页 + 按名称/芯片号/主人模糊查询、宠物照片上传（`MultipartFile` → 存本地目录 → `pet.photo_path` 存相对路径）
- 校验：`chip_no` 唯一（重复时抛"芯片号已存在"）、必填项、照片限 jpg/png 且 ≤5MB
- 权限：主人只能看/改自己的宠物（在 service 里按 `owner.user_id == 当前 userId` 过滤）

**验收**
- 一户多宠：同一主人可建多只，列表按主人筛选正确
- 重复芯片号返回 400 而不是 500
- 主人账号访问别人的宠物 → 403 或"无此数据"
- 上传图片能在界面显示，`photo_path` 里是路径不是二进制

## L3 免疫 + 就诊 + 到期提醒

**交付**
- `vaccine`：新增接种记录，按疫苗种类自动算 `next_due_date`（如狂犬 1 年、联苗 1 年、驱虫 3 个月——周期放常量类，答辩可讲"可配置"）
- `medical`：就诊记录增查
- `Spring Task`：`@Scheduled(cron="0 0 8 * * ?")` 每天 8 点扫 7 天内到期且 `reminded=0` 的疫苗 → 生成站内消息 → 置 `reminded=1`
- 站内消息：本轮先用 `notice` 表 + `user_id=0` 的"系统消息"记录，或加内存队列（二选一，**不新增表**；若要新增表需回到开题报告确认）

**验收**
- 造一条 3 天后到期的疫苗 → 手动触发任务 → 消息出现、`reminded` 变 1 → 再触发一次不重复提醒
- 就诊记录与宠物关联正确，删除宠物时被外键挡住（提示先处理记录）

## L4 寄养 + 领养（含回访）

**交付**
- `foster`：主人提交申请（选宠物 + 起止日期）→ 工作人员审核（通过/驳回）→ 到期置 `FINISHED`；日期区间不合法要拦
- `adoption`：主人申请领养 → 工作人员审核 → 通过后宠物状态变化 → 记录回访（`follow_up_time`、`follow_up_result` 扩展字段）
- 状态机显式写：`PENDING → APPROVED / REJECTED`、`APPROVED → FINISHED`，非法流转抛业务异常

**验收**
- 状态机非法流转（如已驳回再审核）返回明确提示
- 领养通过后同一宠物不能再被申请（加"同一宠物仅一条有效申请"校验）
- 回访记录保存在 `adoption` 表扩展字段里，**表数量仍是 9**

## L5 公告 + 数据看板

**交付**
- `notice`：管理员/工作人员发布、编辑、删除、列表（主人只读）
- 看板 `/stat/overview`：宠物总数、本月新增、待审核寄养/领养数、7 天内疫苗到期数、按品种分布
- 权限：`stat:view`

**验收**
- 看板数字与手工 SQL 核对一致（截图对比写进论文）
- 主人账号看不到看板入口（前端隐藏 + 后端 403 双保险）

## L6 前端（Vue 3 + Element Plus + Vite）

**交付**
- 登录页、主框架（侧边菜单 + 顶栏 + 内容区）、按 `permissions` 动态渲染菜单
- 页面：宠物档案（列表/表单/照片）、主人管理、免疫记录、就诊记录、寄养审核、领养审核、公告、看板
- `axios` 拦截器：自动加 `Authorization`、401 跳登录、非 200 弹 `ElMessage`

**验收**
- 三种角色登录看到三种菜单
- 表单校验（必填、手机号格式、日期区间）
- 401 自动回登录页，令牌过期不白屏

## 开工前需要你拍板的两件小事

1. **题目写法**：`基于 SpringBoot 的…的设计与实现`（任务书表格）还是 `基于 Spring Boot 的…设计与实现`（开题提纲行），以学院/格子达登记为准。
2. **站内消息**：疫苗到期提醒的消息放 `notice` 表（不新增表，当前实现）还是新增第 10 张 `message` 表（需改开题报告的"9 张表"表述）。
