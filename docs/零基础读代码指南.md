# 零基础读代码指南（Java 没学过也能看懂）

> 这份文档不教你 Java 语法，只教你**这套系统是怎么跑起来的**、**哪段代码管什么事**、**想改某个功能该动哪个文件**。
> 建议顺序：先读第 1、2 章（半小时，建立整体感），再按第 6 章的顺序一天啃一层。

---

## 1. 先用一句话说清这套系统

**浏览器里的 Vue 页面，通过 HTTP 请求，调用 Java 后端接口，后端去 MySQL 读写数据，再把 JSON 结果返回给页面渲染。**

```
┌────────────────┐   ①点击"查询"    ┌──────────────────┐   ②SQL    ┌──────────┐
│  Vue 前端       │ ───────────────▶ │  Spring Boot 后端 │ ────────▶ │  MySQL   │
│  127.0.0.1:5173 │ ◀─────────────── │  127.0.0.1:8080   │ ◀──────── │ pet_store│
└────────────────┘   ④JSON 返回      └──────────────────┘   ③结果    └──────────┘
        │                                     ▲
        └──────── ③请求头带 token ────────────┘
```

四个关键事实（记住这四个，后面全通）：

1. **前端不直接碰数据库**，它只会"发请求"。
2. 每个请求都要带一个 **token**（登录时后端发的字符串），后端靠它知道"你是谁、什么角色"。
3. 后端每个接口都有**权限码**，角色表里没有这个码就返回 403。
4. 后端永远返回同一种结构 `{"code":200,"message":"成功","data":...}`，前端只认这一种。

## 2. 一次请求的完整旅行（拿"查宠物列表"举例）

这是全篇最重要的一节：看懂这一条链路，其它接口都是复制粘贴。

### 第 0 步：登录，拿到 token

前端 `src/frontend/src/views/Login.vue` 提交账号密码 →
`src/frontend/src/api/index.js` 里的 `login()` →
`POST http://127.0.0.1:8080/api/auth/login`

后端：`controller/AuthController.java` 的 `login()` →
`service/AuthService.java` 用 `SysUserMapper` 按用户名查 `sys_user` 表 →
用 `BCryptPasswordEncoder.matches()` 比对密码（数据库里存的是加密串，不是明文）→
`security/JwtUtil.java` 生成 token（里面装了 userId、username、roleId）→
返回 `LoginVO`（token + 角色 + 权限码列表）。

前端把 token 存进 `localStorage`（`stores/user.js`），之后每个请求由 `api/request.js` 自动加请求头。

### 第 1 步：前端发请求

`views/pet/PetList.vue` 里 `loadData()` 调 `api/index.js` 的 `pagePet(params)` →
axios 实例发 `GET /api/pet/page?pageNum=1&pageSize=10&keyword=豆` →
请求头 `Authorization: Bearer eyJhbGci...`

### 第 2 步：请求先过拦截器（不是直接进 Controller！）

`config/WebConfig.java` 把 `security/AuthInterceptor.java` 注册到所有路径上，所以请求先到这里：

1. 取出 `Authorization` 头，去掉 `Bearer ` 前缀
2. `JwtUtil.parse()` 解析，失败就直接返回 401 JSON，**不会**进业务代码
3. 成功则把"当前登录人"放进 `UserContext`（ThreadLocal，相当于给这个线程挂了个便签）

同时 `WebConfig` 里排除了三类路径：登录接口、`/error`、以及 `/files/**`（照片用 `<img>` 加载，带不了请求头，不排除会被误判成未登录）。

### 第 3 步：进 Controller

`controller/PetController.java`：

```java
@GetMapping("/page")
@RequirePerm("pet:list")
public Result<PageResult<PetVO>> page(PetQuery query) {
    return Result.ok(petService.page(query));
}
```

三句话读懂：
- `@GetMapping("/page")` = 这个方法是处理 `GET /pet/page` 的
- `@RequirePerm("pet:list")` = 调用前必须过权限检查（主角是 `security/PermAspect.java`：拿当前角色的权限码和 `pet:list` 比对，管理员是 `*` 全通，否则抛 403）
- `petService.page(query)` = 真正干活的是 Service，Controller 只做"接参数、返结果"

### 第 4 步：Service 做业务判断

`service/PetService.java` 的 `page()` 里做了几件"业务上必须"的事：

1. 判断当前是不是**宠物主人**（roleId == 3），是的话只能看自己名下的宠物 → 调 `OwnerService.findByUserId()` 拿 ownerId 再过滤
2. 用 MyBatis-Plus 的 `LambdaQueryWrapper` 拼 SQL（`like(petName or chipNo)`、`eq(ownerId)`、按建档时间倒序）
3. `petMapper.selectPage(...)` 执行，一次查出 10 条
4. 再批量查这些宠物对应的主人姓名（`selectBatchIds`），**避免每条宠物查一次主人**（这叫 N+1 问题，是本项目刻意优化的点，论文里可以写）

### 第 5 步：Mapper 生成 SQL

`mapper/PetMapper.java` 是个空接口，只继承 `BaseMapper<Pet>`。SQL 由 MyBatis-Plus 按实体类注解生成：

```java
@TableName("pet")
public class Pet {
    @TableId(type = IdType.AUTO)
    private Integer petId;     // 对应列 pet_id（开了驼峰转下划线）
    private String petName;    // 对应 pet_name
}
```

所以**不用写 XML、不用手写 SQL**，这是 MyBatis-Plus 相比原生 MyBatis 省事的地方（论文"技术选型"可以对比着写）。

### 第 6 步：返回

`common/Result.ok(data)` → JSON → 前端 `request.js` 拦截器判断 `code === 200` 就把 `data` 交给页面；不是 200 就 `ElMessage.error(message)` 弹红条。

> 全局兜底：任何没被业务代码处理掉的异常，都会被 `common/GlobalExceptionHandler.java` 抓成统一格式（比如数据库外键拦住删除 → 翻译成"该数据已被其它记录引用，无法删除或修改"）。

## 3. 后端目录：每个包管什么

```
src/backend/src/main/java/com/ningcong/petstore/
├─ PetStoreApplication.java   启动类（main 方法在这里；加了 @MapperScan 和 @EnableScheduling）
├─ common/                    全项目公用的小工具
│   ├─ Result / ResultCode    统一响应体与状态码
│   ├─ BusinessException      业务异常（"芯片号已存在"这类，带 code 和中文提示）
│   ├─ GlobalExceptionHandler 全局异常兜底，保证前端永远拿到统一结构
│   ├─ PageQuery              分页入参基类（页码/条数/关键字 + 越界保护）
│   └─ PageResult             分页出参（total + records）
├─ config/                    配置类
│   ├─ BeanConfig             把 BCryptPasswordEncoder 注册成 Bean
│   ├─ MybatisPlusConfig      分页插件（不装它 selectPage 不会真分页）
│   └─ WebConfig              注册拦截器、静态资源映射（照片）、跨域
├─ security/                  登录与权限
│   ├─ JwtUtil                生成/解析 token
│   ├─ AuthInterceptor        每个请求先验 token
│   ├─ LoginUser / UserContext 当前登录人（ThreadLocal）
│   ├─ RequirePerm            自定义注解，写在方法上声明权限码
│   └─ PermAspect             切面，读注解并对权限码
├─ entity/                    和数据库表一一对应的类（Role、SysUser、Pet…9 个）
├─ mapper/                    MyBatis-Plus 的 Mapper 接口（增删改查由框架生成）
├─ dto/                       前端传进来的参数（Data Transfer Object）
├─ vo/                        返回给前端的展示对象（View Object，可脱敏、可拼字段）
├─ service/                   业务逻辑（判断规则都在这里）
├─ controller/                接口入口（只接参、调 service、返 Result）
├─ task/                      定时任务（VaccineReminderTask 每天 9 点扫疫苗到期）
└─ init/DataInitializer       首次启动时建三个演示账号
```

**为什么 entity / dto / vo 要分三个？**（论文答辩常问）
- `entity` 对齐数据库列，内部用，包含 password 这种敏感字段
- `dto` 只收前端允许传的字段（比如新增用户时不能传 createTime）
- `vo` 只给前端需要的字段（比如手机号在这里脱敏、免疫记录在这里算出 `daysLeft`）
三者分开，改接口不会牵动数据库结构，也不会把密码之类的字段漏给前端。

## 4. 六个必须认识的注解（遇到不认识的注解先回来查）

| 注解 | 作用 | 一句话理解 |
|---|---|---|
| `@RestController` | 标在 Controller 类上 | "这个类的方法返回对象，自动转成 JSON" |
| `@GetMapping/@PostMapping("/x")` | 标在方法上 | "什么路径 + 什么请求方式进这个方法" |
| `@Service` / `@Mapper` | 标在类上 | "交给 Spring 管理，用到时自动注入" |
| `@Autowired` / 构造器注入 | 标在字段/构造器 | "我需要另一个类，帮我拿一个来" |
| `@RequirePerm("pet:list")` | 本项目自定义 | "调我之前先查权限码"（由 PermAspect 执行） |
| `@Transactional` | 标在方法上 | "这一串数据库操作要么全成功，要么全回滚"（领养过户、用户删除都用到） |

另外 `@Data`（Lombok）会自动生成 getter/setter/toString，所以你看不到 `getPetName()` 这样的方法体——它们是编译期生成的，不是丢了。

## 5. 前端目录：每个文件管什么

```
src/frontend/
├─ vite.config.js        开发服务器 + 把 /api 代理到 8080（避免跨域）
├─ src/main.js           创建 Vue 应用，装上 Element Plus、Pinia、Router
├─ src/App.vue           最外层容器，只放 <router-view/>
├─ src/router/index.js   路由表 + 全局守卫（没登录跳登录页；没权限的菜单不进）
├─ src/stores/user.js    Pinia：存 token/用户信息/权限码，提供 hasPerm(code)
├─ src/api/request.js    axios 实例：自动加 token、统一拆 data、401 跳登录
├─ src/api/index.js      按模块列出所有后端接口（pagePet/login/auditFoster…）
├─ src/layout/MainLayout.vue  左侧菜单 + 顶栏 + 内容区（后台管理经典布局）
└─ src/views/            每个页面一个 .vue 文件（列表页 = 搜索 + 表格 + 分页 + 弹窗表单）
```

**一个典型的列表页（PetList.vue）包含五块**，看懂一块就懂全部列表页：
1. 顶部搜索表单（`el-form` + `el-input`），点"查询"重新拉数据
2. 表格（`el-table`）：列 = 后端返回的字段
3. 分页（`el-pagination`）：改页码再拉数据
4. 新增/编辑弹窗（`el-dialog` + `el-form` + 校验规则），提交调 POST/PUT
5. 权限控制：按钮上 `v-if="userStore.hasPerm('pet:add')"`，没权限直接不渲染

## 8. 术语表（看不懂就查这里）

| 词 | 意思 |
|---|---|
| Spring Boot | Java 的"开箱即用"框架，帮你把 Web 服务器、数据库连接都配好 |
| 依赖注入（IoC） | 类里不自己 `new` 对象，由框架把现成的塞进来（`@Autowired`） |
| Controller / Service / Mapper | 接请求 / 写业务 / 碰数据库，三层各管一件事 |
| MyBatis-Plus | 对 MyBatis 的增强，单表增删改查不用写 SQL |
| DTO / VO / Entity | 收参数 / 返展示 / 对齐数据库 |
| JWT | 一种"自带签名的小纸条"，后端不用存会话就能认出你 |
| BCrypt | 一种不可逆的密码加密方式，数据库泄露也拿不到明文 |
| ThreadLocal | 给"当前这个请求线程"挂便签，用来存当前登录人（同一个请求内随处可取） |
| 拦截器 Interceptor | 请求进 Controller 之前的一道路卡（本项目用来验 token） |
| 切面 AOP | 在方法执行前/后插一段逻辑（本项目用来做权限检查） |
| 事务 @Transactional | 多条 SQL 要么全成功要么全回滚（领养过户必须整体成功） |
| 前后端分离 | 前端只管画页面、发请求；后端只管数据；两边靠接口契约（`docs/接口清单.md`）沟通 |
| 状态机 | 用有限个状态 + 允许的流转来表示业务流程（寄养：待审核→寄养中→已结束） |
| 幂等 | 同一个操作执行多次，结果和执行一次一样（提醒扫描第二次生成 0 条） |
| N+1 查询 | 查 1 条主记录又为每条查 1 次关联表，本项目用批量查避免了 |

## 9. 答辩时最可能被问的 8 个问题（提前想好答案）

1. **为什么用户表叫 sys_user？** `user` 是 MySQL 保留字，直接建表会报语法错误，所以改名并在论文里说明。
2. **权限怎么做到"菜单看不到 + 接口调不通"？** 前端按权限码过滤菜单（只影响体验），后端 `@RequirePerm` + 切面才是真正的门（staff 手工发请求也会 403，见 TC-09）。
3. **JWT 有什么缺点？** 无状态所以没法主动踢人；本项目用 2 小时过期 + 前端清 token 缓解，真实场景可加 Redis 黑名单。
4. **提醒怎么保证不重复？** `vaccine.reminded` 标记位 + 生成成功后置 1，重复扫描生成 0 条（TC-38）。
5. **为什么回访不单独建表？** 开题报告定了 9 张表，回访是领养记录的从属信息，用两个扩展字段存符合第三范式的取舍（论文里要写明这是设计取舍，不是遗漏）。
6. **领养通过为什么要事务？** 要同时改 adoption 状态和 pet.owner_id，任何一步失败都会导致"人宠关系"错乱。
7. **统计的 SQL 在哪？** `mapper/StatMapper.java`，三个 `@Select`：按月分组、按状态分组、按到期区间 SUM CASE。
8. **并发会不会重复建档？** 芯片号有唯一索引，并发插入时数据库兜底，第二个请求返回 400（TC-82）。
